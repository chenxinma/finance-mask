## 三、详细评审意见

### 一、需求说明（第三章）

#### 1.1 正则规则过于粗糙（FR-02.2 / FR-02.3）

| 问题 | 现状 | 建议 |
|------|------|------|
| 金额正则 FR-02.2 | `\d{1,3}(,\d{3})*(\.\d{2})?` 无法匹配无千分位（12345678.90）、负数（-1,234,567.89）、纯整数（10000） | 扩展为多模式组合正则，覆盖千分位/无千分位/负数/整数 |
| 机构名正则 FR-02.3 | `[\u4e00-\u9fa5]{2,4}(公司\|集团\|银行\|证券\|基金)` 限定 2-4 字，但"中国建设银行股份有限公司"等超过 4 字 | 放宽至 `{2,20}`，支持英文/数字前缀 |
| 关键字列表 FR-02.4 | 仅 6 个关键字 | 补充：负债、净资产、现金流、毛利率、应收账款、预付款、应付账款等 |

#### 1.2 优先级调整

| 需求 | 当前 | 建议 | 理由 |
|------|------|------|------|
| FR-04.5 账号/合同号脱敏 | P1 | **P0** | 账号/合同号是核心敏感信息 |
| FR-03.4 ruamel.yaml 保留格式 | P1 | **P0** | "策略可审"理念依赖此能力 |

#### 1.3 缺失的关键需求

- **FR-04.8 --dry-run 预览模式**：执行脱敏前先看到拟修改位点清单，不做实际写入
- **Strategy.version 字段**：策略文件格式版本化，支持向后兼容
- **自定义规则加载机制**：PatternRegistry 提到"用户自定义规则"，但未定义规则配置文件格式和加载路径

---

### 二、架构设计（第四章）

#### 2.1 组件视图中的循环依赖风险

- scanner 内部模块均依赖 column_matcher 和 patterns，当前无循环依赖
- **建议**：patterns 中仅保留纯正则匹配逻辑，上下文感知放入 column_matcher

#### 2.2 时序图缺少错误分支

- 4.4 节时序图只描述"快乐路径"
- **建议**：增加 alt 组合片段，覆盖异常路径

#### 2.3 FR-04.6 "保留公式"的实现难度被低估

- openpyxl 替换单元格值时，公式会丢失
- **建议明确策略**：公式单元格不参与脱敏，或在脱敏时自动将公式转为值并记录到日志

---

### 三、数据模型（第六章）

#### 3.1 Location 模型字段约束

- **建议**：补充 Pydantic v2 校验代码示例，使用 `model_validator` 实现跨字段约束

#### 3.2 Site.redacted_value 生命周期

- 该字段仅在"执行脱敏"阶段填充
- **建议**：拆分为 StrategyGenerate 和 StrategyExecute，或通过 Optional 明确标注生命周期

#### 3.3 审计日志路径问题

- `AuditLog.file` 仅为文件名，无法区分同名文件
- **建议**：增加 `source_path`（绝对路径）和 `source_filename` 字段

---

### 四、算法设计（第八章）

#### 4.1 金额降低精度算法边界处理

缺失场景：
- `value = 0` → 输出 "0.00百万元" 是否合理？
- `value < 0` → 负数降低精度语义
- `unit` 参数非法值 → 如 "trillion"

#### 4.2 随机扰动总量守恒算法缺失

**建议补充算法**：
```
1. 生成 N-1 个随机扰动因子
2. 第 N 个因子 = -(前 N-1 个之和)
3. 对第 N 个因子做限幅处理（±percentage 范围内）
4. 若超限则重新采样
```

#### 4.3 零宽字符水印容量计算

- payload 约 80 字节 = 640 bit = 640 个零宽字符
- 短文本框嵌入 640 个零宽字符会破坏排版
- **建议**：嵌入前检测目标文本长度，过短时跳过或合并到下一个嵌入点

#### 4.4 扫描去重规则

- **建议**：改为"合并去重，敏感类型取并集"，避免丢失信息

---

### 五、异常处理（第九章）

#### 5.1 新增错误码

| 错误码 | 场景 |
|--------|------|
| E008 | 策略中位点在文件中已不存在（文件被手动修改） |
| E009 | 金额脱敏模式参数不合法（如 percentage: 200） |
| E010 | 水印嵌入失败（如文本框不可编辑） |
| E011 | YAML 策略中 action 值不合法 |

#### 5.2 重试机制

- 文件被占用（E005）等临时性错误建议重试 3 次，间隔 1 秒

---

### 六、非功能性需求（第十章）

#### 6.1 性能基准

- **建议**：补充测试硬件环境、测量工具（time + tracemalloc）

#### 6.2 文件不落地与实现矛盾

- openpyxl/python-pptx 保存时会产生临时文件
- **建议**：明确临时文件清理时机和加密策略

#### 6.3 合规性说明

- 是否符合《个人信息保护法》（PIPL）
- 日志中原始值是否需要加密存储
- 是否需要数据出境评估

---

### 七、实施计划（第十二章）

#### 7.1 时间规划

- 3 周完成全部 4 个阶段过于紧凑
- **建议**：延长至 4-5 周，或先完成 Excel 扫描再做 PPT

#### 7.2 里程碑验收标准

| 里程碑 | 建议补充 |
|--------|----------|
| M1 | 扫描准确率 ≥ 95%（人工标注测试集） |
| M2 | 与人工计算结果比对误差为 0 |
| M3 | 测试用例覆盖 ≥ 20 个场景 |

---

### 八、其他建议

| 建议 | 说明 |
|------|------|
| 水印嵌入备注栏 | PPT 备注栏是易被忽略的位置，适合嵌入水印 |
| global_params 字段 | 允许策略文件顶层定义全局参数，各位点可继承或覆盖 |
| 日志追加模式 | 多次脱敏操作支持追加到同一日志文件 |
| 策略对比功能 | 对同一文件不同时间的策略自动对比差异 |
