## P0：C1 — 数值 cell 写入非数字文本缺类型标记

### 问题

`xmlsurgeon.rs` 的 `set_cell_text` 对无类型 cell（`CellType::None`，即原始 `<c r="B5"><v>1234567890.12</v></c>`）写入非数字文本（如 `"1*,***,***.**"`、`"[公司A]"`、`"622*****7890"`）时，输出变为 `<c r="B5"><v>1*,***,***.**</v></c>`——**没有 `t="str"` 标记**。strict reader（openpyxl）会拒绝这种文件（`ValueError: invalid XML`），Excel 会提示修复/丢失数据。

影响范围：
- 所有原始为数值的单元格（金额、数量列）接受非数值脱敏结果时触发
- 水印嵌入同样受影响（`embed_watermark_xlsx` 对非字符串 cell 追加零宽字符）

### 根因

当前分类逻辑：
```rust
// xmlsurgeon.rs cell_to_string-like 分类（在 set_cell_text 内）
CellType::None => // 原始 cell 无 t 属性（数值 cell）
    new_v_content = new_text.to_string(); // 直接写文本，不改类型
```

rust side 的 `set_cell_text` 构建替换 cell 时保持原始开标签（含 `s=` 样式属性），但如果原始是 `<c r="B5">`（无 t 属性），新 cell 仍然是 `<c r="B5">`——而写入的是非数字文本。

### 修复方案

在 `set_cell_text` 的非 shared-string 路径中，增加**类型判断**：

```rust
// 伪代码——修改 xmlsurgeon.rs 的 set_cell_text 核心逻辑
let new_v_content = match cell_type {
    CellType::SharedString => {
        // 现有逻辑：追加到 sharedStrings.xml，写新索引
        ...
    }
    CellType::None => {
        // 数值 cell → 写入非数字文本时必须改类型
        if new_text.parse::<f64>().is_ok() {
            // new_text 本身是数字 → 保持无类型，直接写数值
            new_text.to_string()
        } else {
            // new_text 不是数字 → 需要改写 <c> 标签加 t="str"
            // 在构建 new_cell 时，将原始标签中的 t 属性加上
            // 开标签改为 <c r="B5" t="str">，其余保持
            needs_type_attr = true;
            new_text.to_string()
        }
    }
    CellType::InlineString | CellType::Formula => {
        // 现有逻辑
        new_text.to_string()
    }
};
```

**具体改动点：**

1. `set_cell_text` 函数增加一个标志 `needs_type_attr: bool`（在 `None` 类型分支设置）
2. 构建 `new_cell` 字符串时：如果 `needs_type_attr && cell_type == None`，在开标签 `<c r="B5"` 后追加 ` t="str"`
3. 水印嵌入 `embed_watermark_xlsx`：同理——追加零宽字符的 cell 如果是无类型，加 `t="str"`

**测试新增：**

## P1：I1 — pptx 输出无水印

### 问题

`executor.rs` 的 `execute_ppt` 方法在保存文件和导出审计后，**没有嵌入水印**。Python 的 `_execute_ppt` 在保存后调用 `WatermarkEncoder.embed_to_ppt`。

### 修复方案

在 `execute_ppt` 的 `if !dry_run` 块中，保存 editor 后加水印嵌入：

```rust
// executor.rs execute_ppt 末尾
if !dry_run {
    if let Some(editor) = editor {
        editor.save(output).map_err(ExecError::PptWriter)?;
    }
    // 新增：pptx 水印嵌入
    embed_watermark_pptx(output, &self.operator)
        .map_err(ExecError::PptWriter)?;
    let output_hash = audit::compute_file_hash(output)
        .map_err(ExecError::Audit)?;
    export_audit_log(&audit, input, output, Some(&output_hash))?;
}
```

`embed_watermark_pptx` 的实现：
- 打开 pptx zip（复用 PptxEditor::open）
- payload = `{operator}|{timestamp}|{hash前16位}`（与 Excel 水印格式一致）
- watermark = Watermark::encode(&payload)
- 对每个 slide 的第一个 `<a:t>` 文本追加 watermark（Python 的 embed_to_ppt 逻辑：每张 slide 的首个形状的首个段落首个 run 的 `<a:t>` 文本尾部追加）
- 注意：`PptxEditor::replace_text(slide_idx, old, new)` 目前是 slide-wide 替换——水印场景不需要精确定位，只需在任意 `<a:t>` 尾部追加；可以复用 `replace_text` 对一个已知唯一的短文本做替换，或在 ppt_writer 里加一个 `append_text` 方法

**备选方案（更简单）：** 不用 PptxEditor，直接遍历 slide XML 找第一个 `<a:t>`，在其文本后追加零宽字符。复用 ppt_writer 内部的 zip open/save + XML 字节操作。

**测试新增：**
```rust

    // 执行 pptx redact → 保存 → 打开 → 找零宽字符 → 解码 → 匹配 payload
```

## P1：I3 — 多表 xlsx 的 generate 扫描逻辑

### 问题

Python 的 generate 有**整文件状态判断**：
```python
column_rules_map = scanner.get_column_rules(filepath)
if column_rules_map:   # 任何 sheet 有列规则 → 只扫 extra-text
    sites = scanner.scan_non_data_cells(filepath)
else:                   # 无 sheet 有列规则 → 全量 scan
    sites = scanner.scan(filepath)
```

Rust 的 `run_generate` 无条件调用 `scanner.scan()`——对混合工作簿（Data 有规则 + Form）会扫描 Form sheet，Python 不会。

### 修复方案

在 `main.rs` 的 `run_generate` 中复现 Python 的整文件状态切换：

```rust
let column_rules_map = scanner.get_column_rules(&sheets);
let sites = if !column_rules_map.is_empty() {
    // 有列规则 → 只扫 extra-text（scan_non_data_cells 语义）
    scanner.scan_extra_text_for_column_rules_sheets(&sheets)
} else {
    // 无列规则 → 全量 scan
    scanner.scan(&sheets)
};
```

**需要的新增：** `ExcelScanner::scan_extra_text_for_column_rules_sheets(&self, sheets: &[SheetData]) -> Vec<Site>` — 遍历 Data sheet，对有列规则的调用 `scan_extra_text`。

或者更简单：直接在 main.rs 里组合已有方法（`get_column_rules` → 有非空规则时调 `scan` 的 extra-text 部分）。

**测试：** 构造一个多表 fixture（Data 有列规则 + Form sheet），对比 Python generate 输出。

## P2：I5 — PPT 替换跨多 run 静默无操作

### 问题

PPT 文本可能跨多个 `<a:r>`/`<a:t>` run（样式分割、自动换行等）。`PptxEditor::replace_text` 只在单个 `<a:t>` 内做 old→new 替换——敏感文本跨 run 时替换静默失败。

### 修复方案

方案 A（推荐）：在 `PptxEditor` 加一个 `replace_paragraph_text(slide_idx, shape_idx, para_idx, new_text)` 方法——直接替换段落内所有 run 的 `<a:t>` 为 new_text（合并为单 run）。executor 在 PPT path 中按段落级别替换。

方案 B（简单但不完美）：`replace_text` 增加 fallback——如果在 `<a:t>` 内没找到 old，尝试在整个 slide XML（忽略 `<a:t>` 边界）做一次字符串替换。

**推荐方案 A**：更干净，与 Python 的 `paragraph.text = new_text` 语义对齐。

**测试：** 构造一个跨 run 的 PPT fixture（手工 XML），验证替换成功。

## P2：I8 — load_strategy_yaml 不调用 validate_location

### 问题

`yaml_io.rs` 的 `load_strategy_yaml` 直接用 serde 反序列化，不调用 `validate_location`。手写 YAML 中 sheet 缺失时静默通过，运行时才发现。

### 修复方案

```rust
pub fn load_strategy_yaml(path: &Path) -> Result<Strategy, YamlError> {
    let s = std::fs::read_to_string(path)?;
    let strategy: Strategy = serde_yaml::from_str(&s)?;
    // 新增：校验所有位点的 location
    for site in &strategy.sites {
        validate_location(&site.location)
            .map_err(|e| YamlError::Validation(format!("位点 {}: {}", site.site_id, e)))?;
    }
    Ok(strategy)
}
```

需要在 `YamlError` 加 `Validation(String)` 变体。

**测试：** 写一个缺少 sheet 的 YAML，验证 load 报错。
